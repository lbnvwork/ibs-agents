# Find-dead-code (мёртвый код: живёт только для тестов)

## Правило
**Если символ используется только тестами — это мёртвый код, его надо удалить.** Тесты **не являются обоснованием** существования продуктивного кода: тест проверяет поведение, а не создаёт спрос на API. Появилось «удобно для теста» — переписать тест, а не тянуть код в прод.

Проверка обязательна **в двух точках**: перед созданием PR (дев) и при ревью (лид). Проверяются **все символы из дифа задачи** (новые и изменённые), а не только новые файлы.

## Порядок проверки (5 шагов)
1. **Собери кандидатов из дифа** — символы, которые задача добавила/изменила:
   ```bash
   git diff develop...HEAD --name-only                      # файлы задачи
   git diff develop...HEAD -U0 | grep -E '^\+\s*(export\s+)?(final\s+|abstract\s+)?(class|interface|trait|enum|function|const|public function|private function|protected function)'
   ```
   Фронт: `export const|export function|export class|defineProps|` + имена новых компонентов/хелперов.
2. **Найди использования ВНЕ тестов** (ключевой шаг):
   ```bash
   # PHP: класс/метод живёт вне tests?
   grep -rn --include='*.php' 'ИмяСимвола' api/src api/config api/migrations api/bin | grep -v '/tests/'
   grep -rn --include='*.php' '->имяМетода(' api/src api/config | grep -v '/tests/'
   # PHP: и глубже по репо (вдруг вызов из другого контекста/команды)
   grep -rn --include='*.php' 'ИмяСимвола' api | grep -v '/tests/' | grep -v '/vendor/'

   # JS/Vue: экспорт/функция/компонент вне спецификаций
   grep -rn --include='*.js' --include='*.vue' --include='*.html' 'имяЭкспорта' frontend/src | grep -v '\.spec\.js'
   ```
3. **Учти фреймворк-магию** (см. «Что НЕ мёртвый код») — если символ регистрируется конфигом/атрибутом, grep по имени его не найдёт, и это НЕ мёртвый код.
4. **Вердикт по каждому кандидату:** `мёртвый` (удалить) / `живой` (есть вызов в прод-коде) / `фреймворк/внешний API` (оставить, зафиксировать почему).
5. **Оформи**: удалил — коммит `<код> ref убрать мёртвый код: <что>`; не удалил (исключение) — одна строка в отчёте/PR, почему оставлено.

## Что НЕ мёртвый код (легальные исключения)
- **Тест-дубли и фикстуры:** `Fake*`, `Stub*`, `*TestDouble`, `fixtures/`, `tests/**` — созданы для тестов, так и задумано.
- **Точки входа фреймворка:** `#[AsCommand]`-команды, `#[AsEventListener]`, Messenger-хендлеры, `*Controller`, `*Processor` (API Platform state processors/providers), `*Extension`/`*Type`, Twig/Vue-компоненты, регистрируемые манифестом.
- **DI-теги и автоконфигурация:** `#[AutoconfigureTag]`, сервисы, собираемые компилятором (`InboundHandlerRegistry` и подобные реестры) — вызываются контейнером по тегу, а не прямым вызовом.
- **Ресурсы API Platform / ORM-сущности:** вызовы генерирует фреймворк (getters/setters, `#[ApiResource]`).
- **Публичный контракт по ТЗ:** API для внешних систем (ЛИС/ИМР/FHIR), точки расширения, заявленные в задаче/ТЗ — оставить, зафиксировать ссылку.
- **Профильные шимы/варианты:** реализации под профиль заказчика (`<Module>/<profile>/…`) — используются сборкой по конфигу.
- **DTO/props для слота:** передаются блоком слота, вызов может идти через `props`/`provide`, ищи по имени ключа, а не по имени класса.

## Инструменты (текущее состояние репо)
- **PHP:** `phpstan analyse` (level max, `phpstan-symfony`) ловит часть unused (private-методы/свойства). Расширения для unused **public** (`tomasvotruba/unused-public`) в проекте **нет** — публичные методы, живущие только для тестов, проверяются вручную по шагам 1–4.
- **JS/Vue:** `eslint`/`knip`/`depcheck` в проекте **нет** — проверка ручная (grep по шагам 1–4). Заводить ли линтер unused — отдельная задача, решает Лид/руководитель.
- Ускоритель для фронта (одноразовый скрипт, без зависимостей):
  ```bash
  for name in $(grep -rhoE '^export (const|function|class) [A-Za-z0-9_]+' frontend/src | awk '{print $3}' | sort -u); do
    hits=$(grep -rn --include='*.js' --include='*.vue' --include='*.html' "\b$name\b" frontend/src | grep -v '\.spec\.js')
    [ -z "$hits" ] && echo "КАНДИДАТ (только вне специй не найден): $name"
  done
  ```

## Пример из проекта
`4.13` — инвариант «нет профильных костылей»: `isBakulevo` в прод-коде = **0** вхождений (единственное — инвариант-тест). Такой код в прод не тянем: если флаг/метод существует только для теста — удаляем символ и переписываем тест.

# Sync-env (синхронизируйся)

Восстанавливает контекст агента после сжатия памяти/компрессии или долгого простоя: тянет свежие репозитории и перечитывает ключевые документы.

## Шаги
1. **Обновить код:** `git fetch origin && git pull origin develop` (или `checkout develop → pull → checkout <ветка> → merge develop`).
2. **Обновить docs:** `cd docs && git pull origin main`.
3. **Перечитать правила:** `.clinerules/*.md` — особенно свой `00-role.md` и `20-workflow.md` (роль и воркфлоу).
4. **Перечитать скиллы:** `ls .cline/skills/` и прочитать `SKILL.md` тех, что понадобятся в работе.
5. **Перечитать план/статус:** `03-Задачи/Планы спринтов/Детальный план спринтов.md`, `Текущий спринт.md`, `03-Задачи/Канбан.md`, `09-Служебное/Оперативная сводка.md`.
6. **Перечитать регламенты:** `09-Служебное/Регламенты/` — Воркфлоу, Git-конвенции, Security-чеклист, Статусы, Эскалация.
7. **Выдать сводку:** текущая задача, статус команды, что изменилось, что делать дальше.
8. **Записать конспект** в `.cline/context.md` (5–10 строк: текущая задача, статус, ключевые решения, что дальше) — его читает хук `hooks/context-summary.sh` при старте сессии и после компрессии.

## Правила
- Только чтение (`git fetch/pull` — это не коммит).
- Если ветки разошлись (divergent) — **не merge/commit**, сообщи руководителю.
- Если контекст свежий — читай точечно только устаревшее, не всё подряд (экономия токенов).

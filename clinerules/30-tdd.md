# TDD и тесты

- Тесты пишутся ДО реализации (TDD): сначала скелет теста, затем код до зелёного.
- После реализации — повторно пересмотри тесты: какие кейсы ещё можно покрыть, что изменилось, какие устарели/неактуальны. Выводы отрази комментарием в статье задачи (секция «Тесты (TDD)»).
- Покрывай позитивные и негативные сценарии + security-сценарии (злоумышленник).
- Бэкенд: `docker compose exec php vendor/bin/phpunit`.
- Фронтенд: `docker compose exec node npm run test:unit`.
- E2E — Playwright (сценарии в `docs/05-Тестирование/Сценарии-E2E/`).
- Тесты зелёные — обязательное условие перед PR.
- CI (GitHub Actions) **работает**: при PR в `develop`/`main` запускаются джобы **Backend** (Composer install → миграции + `schema:validate` → test DB → PHPUnit → PHPStan → composer validate/audit) и **Frontend** (npm ci → Vitest → build). Локальный прогон всё равно ОБЯЗАТЕЛЕН перед передачей на коммит/PR: `phpunit` + `phpstan analyse` (бэкенд) + `npm run test:unit` (фронтенд). Результат — обязательное поле отчёта и PR: `phpunit OK (N tests)` · `phpstan analyse OK` · `npm run test:unit OK (N tests)`. «Пусть CI проверит» — не аргумент: CI лишь контрольная точка.
- **Линтеры и стиль — жёсткий режим (fail, без warn-режима).** С 5.31–5.34 в обязательный прогон входят: **PHP CS Fixer** (`@PSR12 + @Symfony`, `--dry-run --diff`), PHPStan с расширениями (`strict-rules`, `deprecation-rules`, **`unused-public`**, `phpstan-doctrine`, `phpstan-phpunit`), `composer-unused`, **Deptrac** (границы контекстов по ADR-002); **ESLint** (flat + vue + sort-imports) / **Prettier** / **Stylelint**; **Knip** (неиспользуемые файлы/экспорты/зависимости фронта). Любое замечание = красный прогон. Договорённость команды: **новый код пишется сразу чисто** — долг не копим (единоразовое приведение кода делает Лид, задача 5.34).
- **Тесты не оправдывают код (мёртвый код).** Если символ (класс/метод/функция/экспорт) используется **только тестами** и нигде в прод-коде — это мёртвый код: удаляем символ, а тест переписываем под реальный сценарий. «Завели метод, чтобы было удобнее тестировать» — не причина тянуть его в прод. Проверка — скиллом `find-dead-code` **перед PR** (дев) и **на ревью** (лид).

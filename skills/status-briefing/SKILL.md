# Status-briefing (оперативный обзор / диспетчер)

Снимает переключение контекста руководителя: собрать картину по команде, актуализировать статусы и дать консультацию «что делать дальше».

## Шаги

1. **Git-состояние (и закоммиченное, и незакоммиченное):**
   - 7 клонов **docs** (`ibs-*/docs`): `git status -s` + `git diff --stat` — правки статей = отчёты агентов и ответы руководителя, которые ещё не закоммичены.
   - 7 клонов **кода** (`ibs-*`): текущая ветка + `git status -s` (незакоммиченный код).
   - клон РП `ibs-docs`: `git pull origin main` + `git status -s`.
   - **PR-ы (код):** `gh pr list` в клоне кода `ibs` — открытые PR, что на ревью, что ждёт мержа; сверь с ветками агентов (`git branch`).
2. **Прочитать:** `09-Служебное/Оперативная сводка.md` + `03-Задачи/Канбан.md` + `03-Задачи/Планы спринтов/Текущий спринт.md` + `03-Задачи/Планы спринтов/Детальный план спринтов.md` (полный бэклог: цель/KPI/оценка/спринт).
3. **Сверить «Комментарии»** в статьях задач — и отчёты агентов, и ответы/решения руководителя, **включая незакоммиченные файлы** в рабочих копиях агентов (незакоммиченный отчёт → ждёт ревью/коммита руководителя).
4. **Обновить:**
   - Канбан — передвинуть карточки (двигает только РП).
   - Оперативную сводку — статусы агентов + «Мои действия» P1/P2; явно пометить: «агент отчитался, файл не закоммичен → нужно ревью + коммит».
   - «Текущий спринт» (`03-Задачи/Планы спринтов/Текущий спринт.md`) — актуализировать статусы задач (✅/🔄/⬜) и добавить новые задачи спринта (файл часто отстаёт от жизни).
   - «Детальный план спринтов» (`03-Задачи/Планы спринтов/Детальный план спринтов.md`) — при переносе задачи в другой спринт: в «Текущем спринте» ⛔, в детальном плане — в целевой спринт **с новым номером**.
5. **Консультация:** что делать руководителю по приоритету: где блокеры (P1), где ждут **ревью + коммита** незакоммиченные отчёты, где ждут ответа агенты (по ответам руководителя в «Комментариях»), кого подтолкнуть, какие пуши ждут отмашки.
6. **Промты для агентов:** в финальном ответе прикладывай готовые промты — текст, который руководитель копирует и отправляет каждому агенту (триггер + что делать + к какой задаче).

## Правила

- Статусы в Канбане двигает только РП.
- Отчёты агентов и ответы руководителя могут быть **незакоммиченными** — это нормальный этап «отчитался → жду ревью/коммита».
- Ответы/решения руководителя — в «Комментариях» задачи (в чат — только пинг). Учитывай их при сверке.
- Если данных мало (агент не отчитался) — сказать явно, не додумывать.
- В финальном ответе всегда присылай промты для агентов (готовый текст запуска для каждого агента, кого нужно подтолкнуть или кому дать задачу).

## Актуализация статусов после мержа (триггер «смержил #N»)
1. Определи задачу по PR: `gh pr view <N>`.
2. Канбан — передвинь карточку: после тестирования → **«Деплой»** (DevOps выкатывает на тестовый контур, версия через скилл `release`); после его отчёта → **«Готово»** (приёмка руководителя на тестовом).
3. Обнови frontmatter `status:` в статье задачи (`testing → deploy → done`).
4. Обнови статус в `03-Задачи/Планы спринтов/Текущий спринт.md`.
5. Добавь комментарий в «Комментарии»: `ДД.ММ.ГГ Кто: текст → кому`.
6. При переводе в «Тестирую» — пинг **Тестеру и Аналитику** (сверка БЖ, если задача меняет правила; иначе пометка «БЖ-сверка: не нужна»).

## Перенос задачи в другой спринт (ОБЯЗАТЕЛЬНЫЙ чек-лист — «не забывать!»)
**Ключевое: при переносе задача получает НОВЫЙ номер (код) целевого спринта.** Перенос без нового номера — ошибка.
1. **Новый код** = `<спринт>.<следующий свободный NN>` (напр. `4.2 → 5.23`, `4.9 → 6.6`).
2. **Переименовать файл статьи** в `Спринт-NN/` с новым кодом; заголовок `# N.N.` внутри — тоже новый.
3. **Frontmatter**: `code`, `sprint`, `branch` (`5_23_...`), `depends_on` — на новые коды.
4. **Обновить все ссылки**: «Текущий спринт» (таблица «Было → Стало»), «Детальный план» (целевой спринт + таблица переноса), «Общий план», зависимости в других статьях, статьи-разборы.
5. **«Текущий спринт»**: исходная строка — ⛔ с новым кодом («перенесена → 5.23»).
6. **Проверка**: `grep -rn '<старый код>' docs/` — старых ссылок быть не должно (кроме пары «Было → Стало»).

## Переход на новый спринт
- «Текущий спринт» переименуй в «Спринт N» → «Пройденные спринты»; заведи новый «Текущий спринт» из «Детального плана».
